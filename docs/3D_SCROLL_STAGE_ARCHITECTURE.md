# 3D Scroll Stage — Architecture

## Purpose

The hero is a pinned, scroll-driven 3D device showcase. Scrolling through it scrubs a turntable of the device and switches between three chapter cards (one per showcase item in `src/data/portfolio.ts`). It must stay legible on mobile and keep the main thread light during scrubbing.

## Layout and scroll

- `HeroScrollStage` (`src/components/HeroScrollStage.tsx`) renders a section that is `h-[320vh]` on desktop and `max-md:h-[240vh]` on mobile, with a sticky full-viewport stage inside it.
- Scroll progress `0..1` is measured from the section's position against `offsetHeight - innerHeight`. A passive `scroll` listener only writes `motion.target`; all visual work runs in one `requestAnimationFrame` loop.
- Motion is damped toward the target (`SCROLL_DAMPING = 0.14` per 60 fps frame, scaled by real frame time).
- Before the user scrolls, an auto-orbit ping-pongs progress over a 16 s period (`ORBIT_OMEGA = 2π/16`). Any scroll locks the orbit. Reduced-motion disables the orbit and the toggle reflects that.
- Act navigation (`goToAct`) scrolls to the centre of the chosen act's range.

## Device rendering: two layers

The stage has a DOM device layer and a canvas layer. Frames are never drawn on the canvas.

1. **DOM device layer** (`deviceRef`): a wrapper sized to the image's contain rect (`getContainRect(getDeviceBox(...), FRAME_ASPECT)`). It holds two `<img>` slots and a sheen strip. All four edges are feathered into transparency with a CSS mask (`maskComposite: intersect`), so the frame blends into the backdrop instead of showing a rectangle. Slots crossfade by `opacity`; the sheen moves by `transform`. Changes are compositor-only.
2. **Canvas layer** (`canvasRef`, `renderStage` in `src/lib/deviceRenderer.ts`): draws the orbit ring and the corner brackets above the device layer. When no frame is ready (`procedural`), the canvas draws the whole device procedurally (shadow, body, screen) instead, and the DOM device layer is hidden.

Canvas size is limited to the device region (`getStageRegion`): the device box plus the orbit ring on desktop, and the upper band on mobile. The backing store is capped at `MAX_DPR = 1`, which is enough for thin lines.

## Frames

- 60 WebP frames, `public/sequence/frame-01.webp` … `frame-60.webp`, each 1280×800 (`FRAME_COUNT = 60`, `FRAME_ASPECT = 1280/800` in `src/lib/frames.ts`).
- `preloadFrames` starts loading after `window.load`. `frameIndexFor(progress)` maps progress to a frame; `selectFrameLayers` returns the two neighbouring frames with alpha for the cross-blend, or an empty list when nothing is ready.
- Frame URLs use `import.meta.env.BASE_URL` so the `/portfolio/` base works.
- Frames are generated by `scripts/generate-3d-sequence.mjs`: puppeteer-core 25.18.1 drives a three.js 0.187.0 scene in a browser, and the output is encoded with libwebp (frames) and libx264 / VP9 (video). Its `--preview` mode writes to the OS temp directory, not the repo.

## Chapter cards

- Each card's opacity is `clamp(1 - (|d| - 0.25) / 0.25, 0, 1)` where `d` is the distance from the card's act centre (`position - (i + 0.5)`). A card is fully visible within a quarter act and gone by half an act, so neighbouring headlines never overlap. The first card's distance is held at 0 for progress below its centre, and the last card's for progress above its centre, so card 01 is fully visible at 0% and the last card at 100%.
- Cards also move `translate3d(0, -d*36px, 0)` and toggle `pointer-events` above a 0.5 weight.

## Mobile

- Below `md` (768px) the device band sits behind the copy. A dimming scrim (`from-obsidian/90 via-obsidian/55 to-obsidian/90`) keeps the copy legible. The device is not moved, because the 844px viewport cannot fit header, device, cards and CTAs without overlap.

## Reduced motion

- `usePrefersReducedMotion` sets `reducedRef`, turns off the orbit (`orbitRef` false, `autoOrbit` state false), and the scroll-driven transforms still apply.

## Scroll-driven sections

- `ScrollSection` reveals content via an `IntersectionObserver` and applies a parallax offset from its `depth` prop.
- `Navbar` tracks the active section with an `IntersectionObserver`.

## Out of scope: Reel Mode

- `public/sequence/hero-showcase.mp4` and `hero-showcase.webm` are generated by the render script, but no UI or code path references them. Reel Mode is out of scope for this round and is not implemented.

## Performance

- Per-frame work during scrub: one `selectFrameLayers`, two `opacity`/`src` writes, one sheen `transform`, one card loop, and a canvas redraw of the ring and brackets. Measured numbers and the headless caveat are in `docs/goldfish_review_report.md`.
